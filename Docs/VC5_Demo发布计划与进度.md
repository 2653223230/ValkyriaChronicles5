# VC5 初版 Demo 发布计划与进度

更新时间：2026-08-23

## 文档用途

本文档是阶段性目标 1 的持续维护清单，用于记录初版 Demo 从“规则与卡牌可正常游玩”到“Windows 发布包可外发”的计划、进度、验收标准和责任分工。

后续每次修改 Demo 规则、卡牌、角色、AI、启动流程或发布配置时，必须先更新对应设计文档和本文档，再编写测试和代码；验证完成后，再把本文档中的状态和验证证据更新为真实结果。

状态统一使用：`未开始`、`进行中`、`阻塞`、`待人工验证`、`已完成`、`不纳入本次 Demo`。

## 发布目标与范围

阶段性目标 1：制作一个可以快速、方便试玩的 Demo。玩家在 Windows 电脑上启动游戏后，可以选择机动突击卡组或射击压制卡组，并与 AI 完成一整局对战，用于验证卡牌加战棋核心玩法的可行性与趣味性。

本次 Demo 的任务优先级：

1. 首先确保游戏规则、回合流程、胜负结算、角色技能和卡牌效果可以正确运行。
2. 核心玩法稳定后，由策划寻找美术资源，再由 Codex 配置到游戏中。
3. 最后进行 Windows 发布配置、构建、打包和外部电脑验收。

本次 Demo 只要求以下内容可正常游玩：

- 机动突击卡组 `deck_vc5_demo_mobile_assault`。
- 射击压制卡组 `deck_vc5_demo_ranged_pressure`。
- 两套卡组使用的 6 名角色、18 种卡牌、角色技能和共用底层规则。
- 玩家与 AI 的 4 种卡组组合：B 对 B、B 对 C、C 对 B、C 对 C。

以下内容不纳入本次 Demo 发布门禁：

- 旧黏液卡组、黏黏卡牌和其他历史卡组的专属效果。
- 与 B/C 卡组无关的旧卡牌自动化测试失败。
- 联网 PVP 的功能扩展；现有联网底层不得因本次修改而被主动破坏。

边界说明：如果旧内容的失败暴露了 B/C 卡组同样会经过的共用底层问题，例如抽牌、死亡、计分、目标选择或回合推进错误，则仍需修复共用底层问题。
