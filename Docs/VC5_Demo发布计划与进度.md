## 发布目标与范围

阶段性目标 1：制作一个可以快速、方便试玩的 Demo。玩家在 Windows 电脑上启动游戏后，可以选择机动突击、旧射击压制或射击压制 C3，并与 AI 完成一整局对战，用于验证卡牌加战棋核心玩法的可行性与趣味性。

本次 Demo 的任务优先级：

1. 首先确保游戏规则、回合流程、胜负结算、角色技能和卡牌效果可以正确运行。
2. 核心玩法稳定后，由策划寻找美术资源，再由 Codex 配置到游戏中。
3. 最后进行 Windows 发布配置、构建、打包和外部电脑验收。

本次 Demo 只要求以下内容可正常游玩：

- 机动突击卡组 `deck_vc5_demo_mobile_assault`。
- 旧射击压制卡组 `deck_vc5_demo_ranged_pressure`，保留作对照。
- 射击压制 C3 `deck_vc5_demo_ranged_pressure_c3`，作为本版低操作与实操教学的主要试玩卡组。
- 三套卡组使用的 9 名角色、26 种卡牌、角色技能和共用底层规则。
- 玩家与 AI 的 9 种卡组组合均纳入无卡死自动对局；本版外部试玩重点是玩家 C3 对 AI 机动突击。

以下内容不纳入本次 Demo 发布门禁：

- 旧黏液卡组、黏黏卡牌和其他历史卡组的专属效果。
- 与 B/C 卡组无关的旧卡牌自动化测试失败。
- 联网 PVP 的功能扩展；现有联网底层不得因本次修改而被主动破坏。

边界说明：如果旧内容的失败暴露了 B/C 卡组同样会经过的共用底层问题，例如抽牌、死亡、计分、目标选择或回合推进错误，则仍需修复共用底层问题。

### 已审核实施方案：强化 AI 行动表现

目标：玩家在不查看日志和规则文档的情况下，也能复述 AI 本次使用的卡牌、行动棋子、目标和结果。

推荐采用“顶部行动提示 + 棋盘高亮 + 最近行动记录”的轻量方案：

1. AI 获得行动权时，状态区显示「AI 行动」，暂时阻止玩家操作。
2. AI 使用卡牌时，在屏幕上方或棋盘上方显示简洁卡牌提示，至少包含卡名、费用和一句效果摘要，例如「AI 打出：奔袭｜向得分区推进」。
3. 先高亮行动棋子和起始格，再显示目标格、目标敌人或移动路线；移动、攻击、伤害、死亡按顺序播放，不能在同一帧全部跳完。
4. 伤害、护盾、击杀和移动结果使用浮动文字或短提示，例如「-2生命」「护盾-1」「击杀 +3分」。
5. 本次行动结束后，在右侧或不遮挡棋盘的位置保留最近 3 条简短记录，例如「AI 打出射击」「步枪兵对骑兵造成2点伤害」。
6. AI 放弃行动时明确显示「AI 放弃行动」；使用主动技能时显示「AI 使用技能：技能名」，不能只展示卡牌行为。
7. 单次普通 AI 行动的基础展示时间建议控制在约 1.5～2.5 秒；后续可再评估加速功能，本轮不先增加复杂播放控制。

表现顺序统一为：`显示卡牌/技能 -> 高亮行动者 -> 显示目标或路线 -> 播放结果 -> 写入行动记录 -> 切换行动权`。

实现边界：

- 由已有游戏事件产生表现队列，不在 UI 中重新计算伤害、目标或得分。
- 当前首版不强制阻塞服务端行动或联网消息；先以事件横幅、高亮和最近行动记录保证结果可追溯，人工复验若仍过快，再增加可跳过的客户端表现队列。
- 不修改底层联网消息语义；Multiplayer 可以复用表现层，但本轮只要求 Solo VS AI 正确。
- 取消、异常或行动无效时必须清空对应表现，不能让 UI 永久停留在「AI 行动」。

验收标准：

- 玩家能从画面看出 AI 使用的卡牌或技能、行动棋子和目标。
- 移动、攻击、伤害、击杀和得分不会同时瞬间完成。
- AI 完成行动后正常切回玩家，不产生重复行动或卡死。
- 自动化测试验证表现队列顺序和结束回调；人工测试判断节奏是否过快、遮挡棋盘或令人厌烦。

### 已审核实施方案：强化得分与关键反馈

目标：玩家随时知道当前比分、得分区控制情况，并在分数变化或对局结束时明确知道原因。

推荐采用“常驻信息 + 即时事件 + 阶段结算”三层反馈：

1. 常驻分数线：在战斗 HUD 固定显示「我方 X/9」「AI Y/9」，使用两条短进度条或清晰数字；分数改变时对应一侧闪动并播放数值增长。
2. 得分区人数：在得分区附近显示简洁信息「我方 2｜AI 1」，棋子进入、离开或死亡时及时更新。
3. 结算预测：主要阶段显示「若现在结算：我方 +2，AI +0」；预测只说明当前棋盘状态，不自动推进阶段。
4. 得分阶段：双方都放弃后，短暂显示中央结算提示，例如「得分区人数 2:1｜我方获得2分」，再播放分数线增长。
5. 击杀反馈：棋子死亡处显示「击杀 +3分」，同时让得分方分数线增长；自爆、自杀等仍按规则给敌方3分，并明确显示得分归属。
6. 伤害反馈：目标附近显示伤害、护盾抵消和剩余生命变化；无伤害或非法行动使用不同提示，避免玩家误以为点击无效。
7. 胜负反馈：结算界面写明「率先达到9分」「牌库耗尽」等具体原因，并列出本局击杀得分和得分区得分汇总。

信息层级：

- 常驻层只保留比分、回合/行动方和得分区人数，避免 HUD 过满。
- 即时层使用短暂浮字和高亮，自动消失。
- 结算层只在得分阶段和对局结束时阻断操作，玩家确认后继续或退出。

实现边界：

- 分数线、人数和预测全部读取权威游戏状态，不在 UI 中维护第二份规则数据。
- 得分区人数必须复用 `Vc5ScoringZone` 的 7 格定义和画面实际占格规则。
- 得分提示必须区分击杀得分、得分区得分和牌库耗尽判负，不能只显示总分变化。
- 联网流程继续由服务器/主机决定实际分数和胜负，客户端只负责展示。

验收标准：

- 玩家在任意主要阶段都能看到双方当前分数和得分区人数。
- 每次分数变化都有来源说明，分数线显示值与游戏状态一致。
- 双方都放弃后正确展示人数比较和本次加分，再进入弃牌阶段。
- 对局结束时玩家能从结算界面直接说出获胜或失败原因。
- 自动化测试覆盖人数变化、三类得分/胜负原因和 UI 状态同步；人工测试判断信息是否清楚且不遮挡关键操作。
