# VC5 初版 Demo 简易卡组方案

记录时间：2026-07-01

最后更新：2026-08-26

## 设计目标

本方案用于制作初版 demo，用于体现游戏核心玩法和魅力，用于验证游戏底层玩法的可行性与趣味性，而不是局限于特定的卡牌、卡组。

核心设计概念：

> 这是一个卡牌 + 战棋的回合制游戏，以卡牌作为玩法核心，通过卡牌控制棋子的行为。棋子也拥有一定的主动行为或者被动技能，但是游戏核心是为了让玩家爽快地打牌。

本次方案重点：

- 卡牌效果尽量简单、直观、易上手。
- 尽量使用角色自身的攻击力、移动力、攻击范围等属性。
- 每张牌尽量只做一件事。
- 角色技能只做风格补强，不抢卡牌核心。
- 移动、攻击、靠近、撤退、护盾、治疗是首版 demo 的主要动作。

## Demo 首发推荐

第一版建议优先做三套：

1. 基础教学卡组：给第一次玩的玩家。
2. 机动突击卡组：展示打牌让棋子冲起来的爽感。
3. 守点防御卡组：展示中央得分区争夺。

射击压制卡组可以作为第四套，因为远程会引入更多射程判断，但也很适合展示棋盘空间。

## 2026-08-25 低操作重设计候选（方案 B2 / C2，待审核）

> 本章节是对方案 B「机动突击」和方案 C「射击压制」的重新设计候选，只用于策划审核与后续筛选。
> 原方案 B、C 以及当前工程中的已实现卡牌均保留不变；本章节中的卡牌尚未实现，不能视为当前可玩效果。

### 本轮设计目标

本轮把操作语法收敛为：

`打出卡牌 -> 最多选择 1 个棋子 -> 系统自动选择目标、路线和落点 -> 直接结算`

具体要求：

1. 大多数卡牌只选择 1 个己方棋子，玩家决定“让谁执行策略”，系统负责其余操作。
2. 少数需要保留精确战术意图的卡牌只选择 1 个敌方棋子，系统自动选择合适的己方攻击者。
3. 全体效果可以不选择对象，打出后直接结算。
4. 不再出现“先选己方棋子，再选敌人，再选格子”的三段式操作。
5. 自动移动仍必须遵守实际画面占格：一个格子最多一个棋子，不能与敌我单位重叠。
6. 攻击继续使用当前 Demo 规则：只结算卡面写明的单向伤害，不产生模板自动反击。
7. 卡牌优先使用棋子的攻击力、移动力和攻击范围，让玩家通过选择不同棋子自然得到不同结果。
8. 自动结算前应在棋盘上预览将要行动的棋子、自动目标和预计落点；如果不存在合法目标或落点，该棋子不能被选中，卡牌不扣费。

### 自动选择的统一规则

为避免“自动”变成不可理解的随机行为，所有自动效果使用下列统一规则：

| 自动行为 | 统一判定 |
|---|---|
| 最近敌人 | 使用画面实际六边格距离；距离相同时优先当前生命更低者，再相同时按稳定的棋子生成顺序决定，不随机变化。 |
| 生命最低敌人 | 比较当前生命值；相同时优先距离所选棋子更近者，再相同时按稳定生成顺序决定。 |
| 向得分区移动 | 在不超过效果允许距离的前提下，选择能让棋子到最近得分格距离最短的合法落点；相同时优先进入得分区，其次优先靠近地图中心。 |
| 远离敌人 | 选择移动后与最近敌人距离最大的合法落点；相同时优先更靠近己方出生区的格子。 |
| 敌人身后 | 选择该敌人相邻空格中，位于“所选棋子当前位置到敌人”连线另一侧的格子；有多个时优先得分区，其次按稳定坐标决定。 |
| 自动攻击 | 只从效果允许且在攻击范围内的敌人中选择；没有合法敌人时，不执行攻击部分，卡面若要求必须攻击则该棋子不可选。 |
| 自动选择己方攻击者 | 只选择当前能合法攻击目标的己方棋子；优先伤害更高者，伤害相同时优先距离目标更近者。 |

设计原则：玩家可以预判自动结果，但不需要亲自点击路线和格子。策略来自“选择哪名棋子、何时打哪张牌”，而不是来自重复点击。

## 方案 B2：机动突击低操作候选卡池

### 定位

机动突击强调“选择一名己方棋子，它就自动冲起来”。骑兵利用高移动力快速接敌，刺客利用高攻击追击残血，斥候利用高移动与 2 格攻击范围抢占得分区。卡组主要在以下三种策略间选择：

- 抢分：自动进入或接近得分区。
- 接敌：自动靠近、绕后或贴身攻击。
- 脱离：自动后撤，避免冲入后无法生存。

角色继续沿用原方案 B 的属性，本轮暂不修改角色技能。

## 两套低操作方案的对比

| 项目 | 方案 B2：机动突击 | 方案 C2：射击压制 |
|---|---|---|
| 玩家最常选择 | 选择“由谁行动”的己方棋子 | 选择己方射手，少量牌选择必须攻击的敌人 |
| 系统主要自动处理 | 敌人、路线、贴身空格、得分格 | 攻击目标、攻击者、后撤格、范围内敌人 |
| 主要策略 | 选谁冲锋、先抢分还是先追击、何时撤退 | 选谁开火、集中击杀还是范围压制、如何保持距离 |
| 角色属性重点 | 移动力、攻击力、攻击范围 | 攻击范围、攻击力、移动力 |
| 预期手感 | 棋子频繁位移，节奏主动 | 棋子移动较少，但自动火力结果清楚 |

## 审核时建议重点判断

1. 自动目标是否仍然给玩家足够策略，还是让玩家感觉结果由系统决定。
2. “选己方棋子自动索敌”和“选敌方棋子自动找射手”是否应该同时存在，还是需要统一成一种交互语法。
3. `瞬移到敌人身后`、`全军推进`、`火力覆盖`是否足够体现卡牌带来的爽快感。
4. 快速行动数量是否过多；推荐构筑中机动突击有 8 张快速牌，射击压制有 6 张快速牌。
5. 范围伤害是否会让三棋子 Demo 的击杀速度过快，尤其是`横扫`、`火力覆盖`、`迫击炮`和`齐射`。
6. 首轮实现建议只从每套推荐构筑中的牌开始，不要一次实现全部 36 种候选牌；其余候选用于替换测试和后续扩展。

## 2026-08-26 方案 C3：射击压制“只需打牌”（已实现，待人工试玩）

> 2026-08-27：本章已实现为独立卡组“VC5 Demo 射击压制 C3”，ID 为 `deck_vc5_demo_ranged_pressure_c3`，不替换旧射击压制。完整门禁 156/156、菜单启动与预览截图 1/1 通过；操作手感与平衡仍需人工试玩。进度与验收见 `VC5_Demo发布计划与进度.md`。
> 本章节不会覆盖原方案 C、C2 或当前工程中的已实现卡牌；在代码和《VC5_已实现可玩卡牌与卡组.md》同步前，以下角色、卡牌和预览均不能视为当前可玩内容。
> 本轮只细化灵感文档中的 3 个棋子与 8 张未划掉的卡牌；被划掉的“炮击支援”暂不纳入。

### 设计目标

1. 大部分操作收敛为：`从手牌拖出卡牌 -> 指向一个己方棋子 -> 预览完整结果 -> 在棋子上松开并结算`。
2. 玩家主要决定“让哪名棋子执行这张牌”，系统负责自动选择敌人、移动路线和攻击结果。
3. `战术移动`和`强行军`是本组仅有的精确选格牌：选择棋子后再选择一个高亮空格，以保留必要的战棋站位控制。
4. 所有自动结果必须稳定且可预判，不使用随机选敌或随机落点。
5. 预览必须和实际结算使用同一套目标、路线、伤害及棋子被动计算；如果没有合法结果，棋子显示为不可选，卡牌不扣费。

被动共通规则：

- “移动”包括卡牌和棋子技能产生的实际位移；原地结算不视为移动。
- 游骑射手的“机动火力”最多保留 1 层，再次移动只刷新提示，不累加伤害。
- 机动火力仅在伤害牌至少对一个目标造成实际伤害后消耗；全部伤害被防护抵消时保留。
- 狙击手只要本回合实际移动过，即使后来回到原格，也不再获得“稳固射击”。
- 火力护卫的额外 1 点伤害每回合最多触发一次；目标规则与卡牌相同，距离相同时优先当前生命更低者。
- 预览必须把上述被动产生的伤害、触发顺序和目标一起显示，不能只显示卡牌基础效果。

### 自动判定规则

| 自动行为 | 规则 |
|---|---|
| 最近敌人 | 按画面实际六边格距离判定；距离相同时优先当前生命更低者，再相同时按稳定生成顺序决定。 |
| 生命最高敌人 | 比较当前生命而不是生命上限；相同时优先距离行动棋子更近者。 |
| 生命最低敌人 | 比较当前生命；相同时优先距离行动棋子更近者。 |
| 自动移动射击 | 优先攻击当前位置已经能攻击的最近敌人，此时不移动；否则选择移动后能被攻击的最近敌人，并移动到所需步数最少的合法空格。落点并列时优先得分区，其次优先靠近地图中心。 |
| 无合法目标 | 该棋子不可被这张牌选中，显示原因，不消耗卡牌和法力。 |
| 棋盘占格 | 路线和落点只能使用 `Game.unity` 实际存在的 34 个棋盘格，并排除敌我双方已占用的画面格；任何效果都不能产生棋子重叠。 |

### 卡牌预览的统一交互

1. 玩家按住并拖动手牌时，卡牌缩小并拉出一条指向鼠标或触点的箭头。
2. 箭头经过可选己方棋子时，该棋子显示青色描边，并立即计算这张牌作用于该棋子的完整结果。
3. 攻击范围使用半透明区域显示；即将受伤的敌人显示红色描边和预计伤害，例如 `预计 -3`。
4. 涉及移动时显示路线箭头、半透明落点棋子和最终攻击范围；精确移动牌则高亮所有合法落点。
5. 临时或永久射程增加使用“当前范围实线 + 新增范围亮色外圈”展示，并在棋子旁显示 `射程 +1（本回合）`或`射程 +1（本局）`。
6. 在合法己方棋子上松开即确认；移出棋子或拖回手牌区域则取消。不可选棋子使用灰色遮罩，并显示简短原因，例如“移动后仍无目标”。
7. 预览期间不扣费、不移动棋子、不修改生命或状态；确认后必须严格按照预览结果结算。

### 数值与体验说明

- `战术移动`是低费快速组合牌，用于启动游骑射手和火力护卫的移动被动；仍然需要选格，是为了保留少量精确站位策略。
- `强行军`从“移动力 +X”确定为 `移动力 +2`，费用 2 且不是快速行动，避免高移动棋子低成本跨越大半张地图后继续连续行动。
- `临时校准`费用 1、持续 1 回合且不叠加，适合作为射击前的快速铺垫。
- `改装瞄具`以策划最后修改为准：费用 3，同一棋子可叠加；固定构筑保留 1 张用于验证永久成长。
- `火力覆盖`以策划最后修改为准：对范围内所有敌人分别造成完整攻击力伤害，角色被动正常加成；平衡性留待人工试玩。
- `重点击破`攻击当前生命最高的敌人并获得 +1 伤害，承担打前排和压低高生命目标的职责。
- `弱点狙击`增加搜索范围但不增加伤害，承担远距离锁定残血目标的职责，避免“超远距离 + 高额加伤”同时出现。
- `移动射击`费用 2、不额外加伤，因为“自动移动 + 自动攻击”本身已经具有较高价值，并且会自然触发三名棋子的不同被动。

### 2026-08-29 C3 开局实操教学与确定性起手（已实现，待人工实操验收）

本版使用已经在本地 Figma 文件 `VC5 Demo 玩家引导 UI` 中确认的 `V2.1 Editable` 六状态方案。教学的目的不是让玩家阅读六张说明页，而是带玩家实际完成一次“按住卡牌、指向棋子、查看预览、松开结算”的完整操作。

#### 教学触发与牌库边界

- 实操教学仅用于从 `Menu.unity` 的 `VC5 Demo 对战`入口进入、玩家使用“VC5 Demo 射击压制 C3”的本地 Solo VS AI 对局；联网、局域网 P2P、非 Demo 对局和玩家使用旧 B/C 卡组时不进入这套 C3 专属实操状态机。
- 玩家在本地 `GameType.Solo` 中使用 C3 时，牌库完成正常随机洗牌后，将其中一张`移动射击`移动到牌库第一位。因此开局第一张实际抽到、手牌最左侧显示的牌固定为`移动射击`；六状态教学是否显示仍按上一条的 Demo 对手条件单独判断。
- 除被调整到第一位的这一张牌外，不重新排序牌库；其余 19 张牌保持本局洗牌后的随机相对顺序，另外 3 张`移动射击`也继续随机分布。
- 固定首抽不得修改卡组张数、卡牌费用、抽牌数量、联网协议或其他卡组的洗牌规则。以后如果更换教学示范牌，必须同时修改本节、教学状态机和首抽回归测试。

#### 六个教学状态

| 状态 | 进入条件 | 玩家可做的操作 | 完成条件 |
|---|---|---|---|
| `INTRO` | C3 教学对局初始化完成 | 点击“试着打出一张牌吧！” | 进入等待拖牌 |
| `WAIT_CARD_DRAG` | 玩家确认目标说明 | 只能从最左侧按住`移动射击`；其他底层点击被阻断 | 开始拖动指定牌 |
| `PREVIEW` | `移动射击`持续拖动并指向己方`游骑射手` | 保持按住并查看实际 C3 预览；移开棋子可返回上一步 | 在游骑射手上松开并成功出牌 |
| `RESULT` | 卡牌已从手牌移除且移动、伤害结算完成 | 阅读落点、攻击目标和机动火力结果，点击继续 | 进入 HUD 说明 |
| `HUD_INFO` | 结果页确认 | 查看左下当前得分、法力和卡牌费用 | 点击继续 |
| `SCORE_FLOW` | HUD 说明确认 | 查看中央七格得分区及一回合流程 | 点击“知道了，开始自由对战”并结束教学 |

#### 操作失败、预览与 AI 暂停

- `移动射击`拖到其他棋子、空白处或手牌区域时不出牌、不扣法力，卡牌返回手牌，教学继续停留在等待状态。
- 指向游骑射手时使用游戏实际的 C3 预览计算与绘制，不在教学层复制另一套伤害或路线规则；预览必须显示自动路线、落点、攻击目标、预计伤害和棋子被动。
- 只有本地 `GameLogic` 已确认该牌成功离开手牌后才能进入结果页。仅检测鼠标松开不算成功，避免取消出牌时教学错误前进。
- 教学开始后到最终按钮关闭前，`AIPlayerVc5Demo`不得执行行动。示范牌作为普通行动结算后可以把底层行动权交给 AI，但 AI 必须保持等待；教学关闭后再依据当前对局状态正常开始行动。
- AI 暂停是 UI 教学门禁，不修改回合规则、当前行动玩家、卡牌是否快速、服务端消息或 Multiplayer/P2P。教学对象被销毁、场景退出或异常关闭时必须自动释放门禁，避免 AI 永久停住。
