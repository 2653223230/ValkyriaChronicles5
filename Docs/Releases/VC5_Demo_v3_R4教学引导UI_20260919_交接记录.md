## 3. 项目规则与不可破坏边界

### 3.1 项目级强制规则

`.codex/rules/default.rules` 当前要求：

- 修改项目时，如果存在与本次修改相关的文档，必须先更新文档，再写代码。
- 测试要适当，不要过度测试；代码防御也要适当。
- 不要占用 C 盘空间；若临时使用任何磁盘空间，工作结束后及时清理本任务产生的临时文件。
- UI 界面中的标题、按钮、提示、弹窗、布局内说明等视觉文案，以及新布局或新视觉方案，必须先在当前本地 Figma 页面形成审核稿，获得策划明确批准后再修改 Unity。

### 3.2 本项目开发边界

- 核心玩法仍是打牌；棋子技能服务于卡牌、卡手补救和策略配合，不应无意中取代卡牌核心。
- R4 教学仅用于玩家选择 C3-V3R4 的本地 Solo Demo。原 C3 六状态教学必须保留。
- 教学局可以为教学需要暂停 AI、固定首张牌和设置输入门禁，但正式局必须恢复正常洗牌、行动权、AI 和资源状态。
- 完成或跳过 R4 教学后，应结束教学局并重新开始一局正式对战；不得沿用教学局的手牌、棋子位置、分数、法力或技能次数。
- 不要为 Demo 教学优化增加联网消息，也不要修改 Multiplayer/P2P 的底层语义。
- 不要把静态 Figma 底图坐标直接套到已经经过玩家操作的游戏画面。运行时框选必须尽量绑定实际卡牌、棋子、技能按钮、选择窗口、HUD 或合法格子的屏幕矩形。
- Figma 是已批准文案、视觉层级和交互意图的合同；实际运行时对象位置是动态定位的事实来源。两者发生冲突时，不能盲从示例截图。
- 自动测试通过只证明既定断言通过，不证明教学易懂、UI 美观、玩家能顺利操作或不同设备均正常。

## 6. 当前 R4 教学的产品目标

- 开局首先让玩家理解：主要操作是打牌，棋子技能用于辅助和配合。
- 教学中让玩家真实拖动最左侧《移动射击》，查看路线、落点、目标和伤害预览，再松开出牌。
- 简短介绍游骑射手、狙击手和战场指挥官的特性/技能；不替玩家教授固定 Combo。
- 真实引导游骑射手使用「侧翼机动」。
- 真实引导战场指挥官使用「战术筹划」：选棋子、点技能、选择并确认弃牌、三选一获得临时指令。
- 说明临时指令只能用于指挥官当前攻击范围内的其他友军，不能指挥指挥官自己；临时牌只能在本回合使用。
- 说明胜利分、中央得分区、普通行动、快速行动、双方放弃和下一轮流程。
- 教学结束后重开正式对局，让玩家自行探索策略和 Combo。

## 7. 当前教学状态机和真实推进条件

R4 教学在代码中包含 11 个状态，但视觉编号仍是 10 页；`03.5` 是未编号的过渡页：

1. `R4Intro`：教学演练说明，可开始或跳过。
2. `R4WaitCardDrag`：框选最左侧《移动射击》和游骑射手，等待真实拖牌。
3. `R4Preview`：玩家按住卡牌查看真实效果预览，松开并成功结算后推进。
4. `R4CardSuccess`：成功出牌后等待 2 秒显示的过渡页，说明接下来介绍棋子技能。
5. `R4Ranger`：分阶段等待选择游骑射手、点击「侧翼机动」、选择一个合法相邻格。
6. `R4Sniper`：介绍狙击手特性；无需强制点击棋子，可以直接继续。
7. `R4Commander`：分阶段等待选择战场指挥官、点击「战术筹划」、点击并确认弃牌、三选一选择临时指令。
8. `R4CommandRange`：说明指挥官攻击范围、可/不可指挥对象和临时牌期限。
9. `R4Victory`：说明 9 分获胜、击杀分与中央得分区结算。
10. `R4Flow`：说明普通行动、AI 行动、快速行动、双方放弃和常用 HUD。
11. `R4Complete`：完成教学并启动一局全新的正式 R4 vs B-AI1 Solo 对战。

关键要求：状态推进必须由对应真实玩家事件驱动。只有 `R4CardSuccess` 的出现使用结算后 2 秒等待；不能用一串定时器代替点击、拖拽、技能、弃牌或选择事件。
