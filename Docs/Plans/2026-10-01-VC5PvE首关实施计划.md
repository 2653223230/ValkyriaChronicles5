# VC5 8×8 PvE 首关 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 制作独立 Windows Unity 原型，从原创标题进入可部署、可出牌、可直接行动的森林遗迹首关，完整结束胜败流程。

**Architecture:** 独立工程放在 `Prototypes/VC5PvE`，与旧项目共享 Git 仓库但有自己的 Assets、Packages、ProjectSettings、缓存和构建入口；不拷贝旧 TcgEngine 回合/网络系统。纯 C# 规则层维护唯一战斗状态，预览、AI 模拟与实际执行使用相同动作计划；Unity 场景只负责输入、显示与动画。

**Tech Stack:** 本机 Unity 2021.3.33f1c1；URP 12.1.13、UGUI、TMP 3.0.6、Test Framework 1.1.33；Windows x64、鼠标键盘。新工程连接 MCP 后通过对应实例进行场景、测试和构建验证。

**Spec:** [规则文档](../../战场女武神5规则与卡牌-v2-20260930-永铃回响风格.md)，[棋子与卡牌设计](../VC5_8x8_PvE首关棋子与卡牌设计_20260930.md)；2026-10-01 用户批准记录优先于旧待审文字。

**实施授权：** 2026-10-01 用户回复“ok，请实现”，批准本计划及六状态界面稿。当前执行采用17张卡组；UI布局沿已审稿，最终场景使用斜俯视森林遗迹。以下旧“待审核/未实现”记录保留为历史，实时进度以本节与执行记录为准。代码开始前，两份设计已记录本次批准。

**执行接口细化：** `BattleState` 含 `Units`、`Hand`、`DrawPile`、`DiscardPile`、`Obstacles`、`Round`、`Revision`、`Phase`；单位含 `Id`、`Role`、`Team`、`Position`、`Hp/MaxHp`、`Ap/MaxAp`、`AttackUsed`、`HealUsed`、`Shield`、`MarkExpiresRound`、`InspireExpiresRound`。牌实例含 `Id` 与 `Kind`。`ActionRequest` 含 `Kind`、`ActorId`、`CardId`、`TargetId`、`Destination`；`ActionPlan` 含 `IsValid`、`Reason`、`Cost`、`Path`、`Request`、`Revision`、`Summary`。`ActionResult` 含 `Success`、`Reason`、`Damage`、`Healing`。`Definitions.Card(kind)` 返回费用、中文名、效果和执行者限制；`GridRules.Reachable(state,unit,maxSteps)`、`HasLineOfSight(state,from,to)` 用于视图范围。`BattleFactory.TryDeploy(state,unitId,position)` 只在部署期调整/交换。敌计划含顺序 `Actions`，玩家结束清理后生成，回合显示预览在副本调用相同结束清理；新玩家回合恢复次数/补牌。

**执行记录：** 采用用户指定工作区内独立新工程隔离，不改旧 Assets，不自动提交；AGENTS 的 Luna 分工与文档先行要求优先于技能的自动提交、工作树及其他模型默认。规则层采用纯C#，可用本地 .NET 在 Unity 初次导入前先运行同源定向检查，再以新 Unity 工程测试/运行/构建验证。素材任务与规则任务文件互不重叠。

**资源与输入实现细化：** 现成 CC0 角色表为32px像素格、品红背景，保留原图，通过原创色键透明 shader 显示；不将品红底带进游戏。中文字体使用获许可的 Noto 字体，不分发系统字体。卡牌支持点击和拖到执行者两种入口；选执行者后选目标/落点再确认，突入先选落点再选邻敌。每轮首动作前换牌使用单独换牌模式/卡面选择，非换牌模式不暗中置换。悬停或选牌详情显示完整职业/射程/视线/状态期限；副本敌方意图放在右侧信息区与棋盘路径上。普通行动也经同一预览确认，ESC取消。部署拖动角色交换格位，并支持点选角色后点部署格的等价鼠标操作。

**规则审查修正：** 初版 ActionPlanner 伤害摘要未包含鼓舞，也未完整预估护卫/盾后 HP 损失。修正统一为纯伤害预测函数，规划与实际结算共用印记/鼓舞、守护、护盾和生命截断计算；预览不得消耗状态或改变HP/牌/AP。确认侧重新校验计划，真实结算消耗一次性状态。增加一个真实带鼓舞/盾的计划→结算一致性检查，不将首版 runner通过当作UI预览已正确。

## Global Constraints

- 基础蓄势、相关增益和示例、局内符印/AP 升级不实现；两项未通过正文保留。印记、鼓舞与护盾按用户确认后的卡面期限实现。
- HP/AP：战士 9/3、法使 5/2、辅助 6/2；1 AP 基础移动分别最多 1、1、2 格；普攻伤害分别 2、2、1，射程分别 1、3、2，每回合一次；辅助基础治疗 2、射程 2、1 AP、每回合一次。
- 初始/补至/上限均 6 张，未出牌保留；每轮首动作前单张换牌一次；无共享法力、无抽空失败。
- 当前有效卡表是推进、重攻击、自身掩护、战士突入、星火印、贯星术、辅助鼓舞共 7 种；不恢复删去的战地援助。暂以当前表格计数为基线：中立各3、职业各2，共17张；起手6、余牌11。牌数询问保留，用户若改总数，先同步 Copies 与断言再执行。
- 标题、部署、战斗 HUD、目标预览、敌回合、结算稿需本地 Figma 审核；规则批准不是 UI 视觉稿批准。Figma 构图稿不充当已达到最终游戏美术效果的证据。
- 每次产品代码前先更新对应设计和本计划；实施后回填数据、规则、场景与文档差异。默认不自动提交、打 Tag 或 push，保留当前工作区的其他修改。
- 新工程不带账号、PvP、网络、RPG 养成、存档或更多关卡；缓存、下载和日志放在工程的忽略目录，不安装新 Unity 或插件到 C 盘。

## Review Focus

1. 拖牌未确认、越界、错误执行者、被遮挡及 AP 不足：牌与 AP 都不损失（任务 2/4）。
2. 换牌遇到空抽牌堆、牌库/弃牌合计不足、倒下角色专属牌：不死循环、不复制牌，非法换牌不消耗机会（任务 3）。
3. 先推位或击杀再看敌方意图：预览与连续敌方动作在同一棋盘上重算一致（任务 3）。
4. 六张手牌、弹窗与敌回合输入：1920×1080/1280×720 不遮住关键格子，敌行动期间不能改变玩家状态（任务 4/5）。
5. 返回标题、重试或结束战斗时仍有动画：不会追加伤害、双开战斗或保留上一局状态（任务 4/5）。

| --- | --- |

公共接口：`GridPos(int x,int y)`（0—7），`BattleFactory.Create(bool fixedOpening)` → `BattleState`，`ActionPlanner.Plan(BattleState, ActionRequest)` → `ActionPlan`（合法性、失败原因、路径、效果、结果摘要），`BattleResolver.Apply(BattleState, ActionPlan)` → `ActionResult`。输入端只提交 `ActionRequest`，不可直接改 HP/AP/牌区。计划带状态修订号，过期预览确认时重算并重新展示。

AI 接口：`EnemyPlanner.PlanTurn(BattleState)` → `EnemyTurnPlan`，在副本上逐敌调用同一规划/结算规则；真实执行使用这份动作顺序并检验修订号。结束玩家回合时不能只复用先前 UI 缓存。
