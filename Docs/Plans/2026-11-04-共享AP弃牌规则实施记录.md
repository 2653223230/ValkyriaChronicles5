# 共享 AP 弃牌规则实施记录

日期：2026-11-04

## 范围

依据 `Docs/Plans/2026-11-04-共享AP交互V2实施.md` 的规则项，本次仅调整共享 AP 结束回合的弃牌 API、相关 EditMode 规则测试及检查工具调用审查；个人 AP 规则和控制器/UI/PlayMode 均不在修改范围内。

## 实施结果

- `SharedRules.EndTurn` 参数改为 `discardIds`。传 `null`/空集合代表零弃；未选中的手牌全部保留；弃牌进入弃牌堆，按既有抽牌逻辑在新玩家回合补至最多 5 张。
- 移除“最多保留两张”限制。弃牌 ID 有重复或不属于当前手牌时返回无效计划，源状态不变；错误原因为“弃牌列表包含重复 ID 或不在手牌中的 ID”。
- 更新共享规则 EditMode 调用：原保留参数迁移成弃牌参数；模拟流程需保留牌时改为弃掉其余牌。
- 新增/调整共享规则覆盖：零弃（包含 null）、全弃、部分弃、补到 5 张、卡牌 ID 唯一、非法 ID 与重复 ID 不推进状态。多回合循环现在明确传入弃牌列表。
- `Tools/RuleChecks/Program.cs` 不调用共享规则 API；其脚本仅编译并运行个人 AP 的 `RulesAcceptanceTests`，没有旧共享规则参数需要迁移。

## API 契约

`SharedRules.EndTurn(SState before, IEnumerable<string> discardIds)`：第二参数表达“本次弃掉的手牌 ID”，不再表达保留 ID。`null`/空集合表示零弃；ID 必须唯一且都属于当前手牌。成功后先弃所选牌，执行敌方回合，玩家回合重置并按既有规则抽牌至最多 5 张。非法列表返回无效计划且不修改源状态。

- 工作区原有未提交修改保持不变。
