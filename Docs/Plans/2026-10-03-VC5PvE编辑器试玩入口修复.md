# Unity试玩入口与编辑器状态修复

用户反馈独立工程Play直接进首关、无响应且Hierarchy/Project消失。

现场证据：Unity主窗口位于VC5PvE/ForestRuins，Play与Pause均蓝色；Game视图最大化。当前停在部署阶段。底栏显示Unity MCP连接错误，原本自动化服务未运行；独立工程仍包含Title与ForestRuins两个场景。

修复范围：解除编辑器暂停、退出Game视图最大化、恢复常规资源面板；检查Error Pause与输入状态，恢复Title作为当前试玩场景，保留直接运行ForestRuins的能力。需要临时Editor诊断脚本时先记录用途：恢复本地MCP连接并读取状态，不改玩法/AP/卡牌。诊断完成移除临时脚本。更新README明确Unity运行当前场景、打包以Build Settings首场景为入口；本轮不打包。

独立工程理由：新版采用8×8单机PvE、逐棋子AP和新牌组，旧工程保留TCG/PvP系统与发布配置。隔离减少无关系统耦合，便于原型验证。该工程拥有自己的Assets/Packages/ProjectSettings及Build Settings，可以独立开发与打包；旧工程的场景/资源须显式迁入，规则改动不会自动同步旧项目。

## 修复与验证结果

- 解除Pause、退出Game最大化，实际截图确认左侧Hierarchy、下方Project与右侧Inspector恢复。资源未丢失。
- 关闭Console的Error Pause。现场存在MCP连接错误，但无法证明是谁/哪次错误开启了暂停；确认暂停本身是本次交互停止的直接原因。
- 加载Title，实际按Play出现开始游戏界面。实际鼠标依次点击开始游戏、开始战斗、守铃者，成功进入己方回合并弹出其移动/普攻菜单，暂停按钮未开启。
- Build Settings保持Title第一、ForestRuins第二，打包入口未缺失。独立工程本身不导致跳过标题；上次交付时当前场景为ForestRuins。
- 已移除临时Editor脚本；游戏运行代码与规则数值未修改。本轮不打包、不重跑与编辑器状态无关的规则测试。
- 收尾退出Play，当前Title场景，常规布局；README已同步入口和Pause/Shift+Space说明。
